# Ready-to-deliver checklist

- [ ] Clear one-sentence use case and 3 observable learning outcomes.
- [ ] Chosen schedule totals 60, 90, or 120 minutes; setup is outside it.
- [ ] All placeholders replaced; attendee pages contain executable, checked instructions.
- [ ] Supported device/OS, SDK/model versions, resources, terms, and network needs stated.
- [ ] At least one learner-authored code/design decision and one new test.
- [ ] Starter, solution, data, and tests actually supplied.
- [ ] Checkpoints define observable pass/fail conditions; no fake expected output.
- [ ] Runtime evidence distinguishes fresh, historical, synthetic, and untested results.
- [ ] Instructor hints, answers, fallback, and time cut decisions prepared.
- [ ] A novice teammate completed the attendee route in a timing pilot.
- [ ] No secrets, private data, unsafe defaults, or unlicensed assets are published.
- [ ] Repository structure check, release placeholder check, and actual runtime checks passed.
